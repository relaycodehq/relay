# Project workspace

The experimental app opens local Git projects without requiring an account or PR. **Add project folder** registers an existing Git root. Gitea sign-in automatically matches its remote and verifies repository identity. Existing linked folders, review state, settings and account data are retained.

The default is a **thread-first chat**: Recent conversations and expandable projects on the left, a centred composer, and no open code panes. Each project contains its threads; search finds threads across projects. A new thread chooses **Repository** or **Review a PR** above the composer. Choosing a PR does not open its diff. The workspace has three peer panes, toggled from the header: **Chat**, **Changes** (the working tree, or **Review** for a PR thread) and **Files** (the inline editor). Drag a header toggle or a pane's title to reorder the panes, and drag the divider between two panes to resize them; order and sizes are remembered. Code panes start closed on launch and thread changes. Files always open inline in the Files pane, including **Edit locally** from a PR review and **Open in editor** from a local diff. A file chip in the chat never opens Files: it selects the file's row in **Changes** and scrolls its diff to the linked line, or selects the file in a PR thread's **Review**. A file without local changes says so and offers **Open in editor**. The editor shows the working file with change bars, and **Compare with HEAD** switches to a side-by-side view. An unsaved buffer keeps the Files pane open and blocks navigation that would discard it. Diffs fall back to a unified layout when their pane is narrow. The cross-project **Pull request inbox** keeps the existing review workflow.

The layout follows T3 Code's ChatView/ComposerSurface: a bounded message column, centred empty-thread composer, compact provider controls, and an inset branch/context strip. The app-owned presentation can change independently of the pristine, updateable T3 streaming modules.

- **Changes** shows staged, unstaged and conflicted files and lazily loads selected diffs. Stage/unstage is explicit. Commit uses only staged content. Push shows the exact remote/branch and outgoing commits before executing a normal non-force push. Stale snapshots require refresh. No automatic checkout, reset, pull or push.
- **Files** opens the syntax-highlighted editor inline, against local HEAD, with undo, search, live TypeScript/Angular checks, definitions and usages. Writes use content/version checks and atomic replacement; unsaved files block navigation that would discard the buffer. Save before quitting.
- **Pull requests** embeds existing lazy diff review, comments, grouping, viewed progress, blame and diagnostics. Discussing selected lines carries exact PR-side/revision evidence; changed PR heads require refreshing.

Each project has multiple local chats, optionally attached to a PR. Select **Codex**, **Claude**, or **Message only** for each message; plain typing invokes the selected agent, and explicit **@codex** / **@claude** mentions override that selection. New private threads default to Codex; newly joined shared conversations default to Message only. Provider, model, reasoning, Fast, permissions and Build/Plan choices are remembered per conversation and per project’s unsent draft. Fresh drafts use Full access and Build, matching T3 Code; existing Ask/Edit selections migrate to Supervised/Auto-accept edits without silently increasing access. Switching projects or restarting restores the saved selections. No agent runs until Send.

The composer model button opens a T3-style picker with provider tabs, fuzzy search, favorites, model shortcuts (Cmd/Ctrl+1–9 while open), and a legacy section. Reasoning and Fast mode are adjacent controls; unsupported reasoning resets to the model default when switching models. Custom Codex IDs can be entered through model search and remain available locally. Provider switching does not send the draft. Claude uses its CLI default; no unsupported provider/model choices are advertised.

Replies open a focused one-level side conversation in the same pane, with **Back to conversation** and reply counts in the main timeline. Replying to a reply uses the original root, rather than creating nested levels. Each Codex side conversation has its own resumable provider session. Drafts survive navigation and reload.

The active turn shows elapsed time, commentary, tool work and Thinking. After completion, that timeline folds behind **Worked for…**, leaving the terminal answer readable. Command/file activity is bounded (80 activity entries, 8,000 characters per command); raw patches and tool arguments are not retained. Tool traces and commentary stay local and are excluded from shared messages. **Open working changes** opens the current working-tree diff. Answers can link to files and lines in the linked clone; only paths inside that clone open in the editor. This is not an immutable per-turn patch history.

Codex uses persistent local sessions with streaming. Requests resume the same session and send subsequent conversation updates rather than retransmitting the entire history. The renderer applies T3 Code's incremental Markdown transformation; the subprocess transport uses pinned pristine T3 protocol modules. See [T3 streaming updates](t3-streaming.md) for the supported upstream update procedure and integrity checks.

Only necessary recent conversation updates are sent, capped to twelve messages / 12,000 characters per message. Earlier private turns remain in the selected harness session where available. Codex and Claude keep separate saved cursors, including focused replies. Sending to the other agent on a branch that already has a session warns first (with a **Don’t show this again** option), then asks the outgoing agent for a handoff note in its own session before the new agent answers; the note is injected into that first prompt as reference data and the timeline shows a **Switched from … to …** divider that expands to the note. A failed or slow note (two minutes) leaves the divider and the switch proceeds with recent messages only. Shared histories are reference data, not instructions to execute other members' requests. Permissions use T3’s native harness mappings: **Supervised** asks before commands and changes; **Auto-accept edits** permits edits and asks for other actions; **Auto** enables the harness’s automatic reviewer; **Full access** permits commands and edits without prompts. Codex receives explicit approval, sandbox and reviewer settings on every turn. Claude uses its official Agent SDK’s permission modes and `canUseTool` callback. External apps/MCP remain disabled in this integration. Legacy PR-room questions and title generation retain their bounded read-only policy.

Approvals appear above the composer with Decline/Approve and an additional menu for session approval or Cancel. Only decisions offered by the harness can be submitted. The native process stays alive between turns so session approvals actually persist; they end when that provider session closes (Stop, app exit, provider failure, or a Claude permission-mode change). Native session identifiers remain saved for resuming conversation context. Pending requests and question answers are transient and local: they never enter shared chat history or the room server. Stop cancels pending requests and pauses queued messages.

**Build/Plan** is separate from permissions. Codex uses native collaboration modes; Claude uses native Plan mode. Harness questions have numbered choices with keyboard shortcuts, one question at a time, and custom answers. A completed proposal has an **Implement plan** action which sends the implementation request in Build mode while preserving any unsent draft. Shared participants receive the final plan text, not permission controls.

Answers are limited to 100,000 characters and ten minutes. Stop keeps partial text. Periodic local checkpoints preserve interrupted output. Shared final-answer delivery retries without running the model again. Chats retain their local history; no automatic deletion or truncation of saved messages occurs. Only recent messages are rendered initially, with an Earlier messages control.

**Share conversation** explicitly uploads its saved history to the configured room server and generates an invitation. Coworkers see completed answers, not your private partial token stream. Everyone runs their own agent in their own clone. Sharing requires no commit and does not upload uncommitted files; it does include code excerpts already present in messages. Sharing location is opt-in; saved-file synchronization is a separate opt-in control.

The [server guide](../server/README.md) explains repository verification, Gitea-token consent, invitations, operator trust, file-sync limitations and upgrades. Sharing does not grant Gitea access. The clone check is a desktop safeguard; authenticated Gitea repository access is independently enforced on the server. Previously downloaded copies of messages cannot be remotely erased.

Not implemented: automatic cloning or branch synchronization, keystroke-level coediting, semantic autocomplete/rename/debugging, arbitrary language servers, per-chat membership isolation, or end-to-end encryption. A committed local Git repository is required; initialize/commit a new empty repository in your terminal first.

While an answer is running, send another message to queue it for its own turn. Queued messages run in order, retain their model/mode/attachments, and can be removed or sent now. **Send now** (the arrow on a queued message) uses Codex's native active-turn steering for text with the same model, permissions and reply context. Claude, screenshots, skill invocations and selected PR lines use separate queued turns. An unavailable or rejected steer stays visible with its explanation and pauses the queue; it is never silently retried.

**Stop** interrupts the active provider, preserves partial output and pauses queued work. **Resume answer** continues the selected harness’s saved session. **Send now** on a paused message restarts pending work. The × action returns its text and attachments to the composer, preserving any existing draft. The local queue survives restarts and always reopens paused. Pending prompts, attachments and private tool/reasoning traces are not shared; messages enter the shared conversation only when sent. Queue limits are 20 messages and 8 MiB of serialized content.

## Composer commands and branch pull requests

Use `/openpr` (or **Create PR** beside Changes) to open the current branch’s pull request or prepare a new Gitea PR. The preview includes target branch, title, description, draft status and any required push. Creation only publishes committed changes after an explicit click; it never stages local edits or force-pushes.

The composer also offers `/changes`, `/files` and `/new`. With Codex selected, enabled skills are discovered from the installed Codex app-server for the project. Type `$logical` anywhere in a message to find a matching skill, or use `/skill:name`; arrow keys and Enter/Tab select it. Selected skills are sent as native Codex skill inputs. Claude currently supports Relay’s local actions, but has no skill discovery in this menu.

## Virtual project folders

Use the folder icon beside **Projects** (or right-click a project) to organize it under a virtual path such as `Work/Frontend`. Other projects assigned the same path share that folder. Clear the path to return a project to the top level. This never moves the checkout on disk. Folder and project expansion states are saved independently and survive app restarts.
